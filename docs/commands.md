# Commands

Every command of `manuscript-guard`, in the groups and the order `manuscript-guard --help`
lists them. Each takes `--help`, which gives its options. `verify` is a separate command
because it executes your analysis, which a gate never does, and because it takes as long
as the analysis does.

## Setup & Guide

| Command | What it does |
|---|---|
| `init` | scaffold a new manuscript project; `--latex` starts the manuscript in LaTeX; `--from paper.docx` brings a paper written in Word in, its tables as pipe tables and its title page set aside; `--english en-GB` or `en-US` declares the paper's English (none unless told); `--github-actions` writes the workflow that runs `check` and `build` on each push and pull request, and in a project set up already writes that alone ([github-actions.md](github-actions.md)) |
| `next` | say what to do now, from one run of every gate: what stops a gate, stale results, the plan, the choices due (journal, English, reporting guideline, study design), the numbers' sources, the other failures, the warnings, the next stage, then the optional steps; each with its skill and the exact command, and a choice as the `set` commands to pick from. Writes nothing; `--json` for an agent ([next.md](next.md)) |
| `set` | write one setting of `paper.yaml` (`stage`, `target_journal`, `english_variant`, `reporting_guideline`, `study_type`) and keep its comments and every other line; it refuses, writing nothing, where the file would read back as anything else |
| `stages` | what each stage means and what binds at it |
| `journal` | list journal profiles, start one from the annotated template, or read a journal's page again against the stored one (`--reread`, and `--page` for a block's page of its own) |
| `style` | fetch the journal's citation style from the CSL style repository once, and keep it in `profiles/journals/styles/` for the offline build |
| `install-skills` | copy the skills to a folder an agent tool reads; `--verify` checks the copy, `--remove` takes it away |
| `report-issue` | write a report of a failure of the tool's own (`--last`, a fingerprint, `--list`) or about a gate or a command that got something wrong (`--about G2 --flagged` or `--missed`, with the text that shows it, checked again on this machine for `audit`, G6 and G14, and a test to start from), or of anything else (`--title`), print it whole and give the issue page's address with it filled in, for you to read and post; the error's message only with `--with-message`; it sends nothing ([failures.md](failures.md)) |

## Checking & Audit

| Command | What it does |
|---|---|
| `check` | run every gate; `--stage submission` holds the manuscript to submission standards |
| `audit` | check a paper that was not written this way, in Word, Markdown or LaTeX, or a PDF through `pdftotext` (each place a page and a line, its tables read as text): its numbers against the outputs `--against` names, if any, and against each other, a flow printed as a list, its Abstract against its Results, its words (G6, G14) and its reference list (G7); `--lookup` asks the registries about each DOI and PMID; for an editor, `--journal` holds the main document to the journal's profile, lists what a .docx holds besides its text, and with `--authors` finds an author named in any document given where the review is blind and with `--lookup` counts the authors' and the journal's own references; for a referee, `--design observational` warns of a causal claim where the paper sums up, `--design trial` of a table of baseline characteristics with a column of P values, and `--cited FILE` lists each citation beside its sentence, with each work's abstract under `--lookup`; `--package` holds the authors' package (.zip or folder, unpacked safely) to its own MANIFEST.yaml, each result to the script packaged beside it, and the paper's numbers to its results, and runs nothing; `--report-draft FILE.md` writes the findings and their places, and what was not checked, as the start of your report ([refereeing.md](refereeing.md)); `--commented FILE.docx` writes a copy of the .docx with each finding as a Word comment at its place; `--pdf FILE.pdf` writes the report as a PDF with bookmarks |
| `screen` | read a file that came from someone else before an agent reads it, a co-author's Word file, a reviewer's letter, a comment or answers file, a stored literature page (a .docx, HTML, Markdown or text, a PDF's text, an e-mail): it quotes each place where the file hides text from its reader (hidden by its formatting or a style, too faint or too small to read, zero-width characters inside a word; in HTML, text the page does not show only where it holds such words) and each place with words that tell a model what to do, each a warning; `import`, `respond --from`, `sync-sources` and `checker import` screen each file they read first, and go on |
| `compare` | for an editor or a referee, set a revised manuscript beside the version before it, a PDF among them: the sections, the tables cell by cell (not in a PDF), the numbers, citations and bindings gone, new or changed, the sentences that claim more, less or the opposite, and the revision audited with each finding marked new or standing; `--response` holds the letter's quotations to both versions, and `--comments` matches your own comments by what they quote or name; `--report-draft FILE.md` writes the findings and their places as the start of your report; it sends nothing, and never says a comment was answered ([refereeing.md](refereeing.md)) |
| `explain` | show how each number in a file was classified, then the sentences of its Results and Discussion that claim and rest on neither a result nor a citation, which `check`'s note counts |
| `bind` | show every unbound number and how to give it a source; `--pointers` offers the `{{ref.…}}` binding that prints each typed "Table 2" |
| `impact` | list what depends on a file, or on each file changed since a commit: results, the sentences that bind them, figures, Methods paragraphs, panel readings and co-author answers |
| `reworded` | check that an edit changed the wording and no binding, citation or typed number, and warn where it made a sentence claim more, less or the opposite |
| `methods` | check or record that the Methods were read against the code; `--explain` lists each claim beside the step that backs it |
| `checklist` | write the completion file for a checklist |
| `fetch` | download a reporting guideline's own checklist document |
| `transcribe` | build checklist profiles from those documents |

## Analysis & Data

| Command | What it does |
|---|---|
| `verify` | re-run the analysis and check it still produces the recorded results, a harvested output among them; `--receipt SITE`, run where the data are held, runs each harvest entry naming the site and writes `receipts/SITE.receipt.json` of what ran and what came out, by digest, refused where an output holds a count the custodian forbids, and warning where a total may give one away |
| `harvest` | take in an output a script writes without the emitter (`.csv`, `.tsv`, `.json`) as `results/<key>.json`, its cells as values and its table as `table.<key>`, by `harvest.yaml`, with the columns that are counts (`--counts`) and a table that is working output (`--not-quoted`); it runs nothing, so `check` warns until `verify` or a site's receipt covers it ([harvest.md](harvest.md)) |
| `vault` | register the folder where the data are held, outside the project, which the operating system keeps from the agent: `init FOLDER FILE...` records each file named by its digest in `design/vault.yaml` and the folder's path in a git-ignored local file, refused for a folder inside the project or a `paper.yaml` with no custodian's minimum cell count, and prints Claude Code's deny rules for the folder (`--agent-settings` writes them, after asking you); `check` says whether this session can read the data, exit 0 not reachable, 1 readable, 2 not registered here; the plugin's hooks say so at each session start, and refuse an agent's command that names the folder while it can be read; `init` also starts `analysis/00_profile.py`, whose `em.profile` writes each file's profile, every count below the minimum held back and any a reader could work out from the rest, no centile the smallest or largest value; `run [SCRIPT...]`, at a terminal, lists the scripts changed since the run released last, asks, runs them on the data in a copy of the project inside the vault and keeps what they wrote in its outbox, the agent told only exit codes and where a script failed; `release RUN --as PERSON`, at a terminal, holds every count of the outbox to the custodian's minimum, releases a file no check reads only where you type its path, and records the release; `synthesize [NAME]` draws `data/synthetic/NAME` from the released profile, the data dictionary and a kept seed, and from nothing else, as CSV or TSV; it sends nothing, and a released file is read by the agent and its provider ([vault.md](vault.md)) |
| `values` | write a LaTeX manuscript's values file, `mgvalues.sty`, so that the `.tex` compiles with the results' numbers in it |
| `models` | print each fitted model as its card, with what G15 says of it |
| `dictionary` | write the data dictionary out for whoever builds the form: REDCap's data dictionary (`--redcap`), one row per variable (`--csv`), or the form's outline in Markdown (`--outline`) |
| `palettes` | list the palettes shipped (MetBrewer, MoMAColors, NatParksPalettes, PNWColors, wesanderson, Okabe-Ito, ColorBrewer, viridis, cividis, Crameri's), with how many colours of each stay apart for readers with a colour-vision deficiency, or show one with its licence |
| `related` | compare the paper with the earlier outputs of the same data in `literature/related.yaml`, value by value; `--take` copies an earlier project's results, plan and data dictionary in, at the revision the author names |

## Literature

| Command | What it does |
|---|---|
| `lookup` | look up each cited DOI and PMID once, search PubMed, Crossref and OpenAlex by its title for a reference with neither, and keep what the registries said in `literature/lookups/`; `--journals` asks the NLM Catalog and DOAJ about each shortlisted journal's ISSN; `--registrations` asks ClinicalTrials.gov, the EU PAS register, OSF or ISRCTN about each registration `paper.yaml` lists, and keeps the answer in `design/registrations/`; `--paper` asks Crossref about the paper's own DOI, and keeps the answer in `communication/lookups/` for `communicate check`; `--resources` asks the RRID resolver about each RRID the main text and the supplement type, and Cellosaurus about each cell line among them, and keeps the answers in `literature/rrids/`, an answer that did not come recorded as nothing |
| `search` | ask PubMed, Europe PMC and OpenAlex for works a claim could cite, each with its identifiers, kind, retraction status, later version and open copy; it proposes, the author chooses, and nothing is written |
| `sync-bib` | rewrite `references.bib` from Zotero |
| `sync-sources` | copy each cited work's PDF or saved page from Zotero into `literature/sources/`, or Zotero's text of it where the file is not on this computer or is an EPUB, and list the works with no copy; `--from` takes the PDFs of a folder named by DOI instead, as a downloader such as auto-paper-harvester saves them, and `--inbox` those of a folder such as the browser's Downloads, each filed by the DOI or title its first pages show. A work none of these gave a full text is then fetched from the web: its open copy, else the PDF its DOI link gives this computer, else its abstract, and the works still wanted are listed with their DOI links (`--no-fetch` turns this off; `--dry-run` fetches nothing). The folder stays out of git in a new project, and `literature/sources.yaml` records what is in it, the files saved by hand among them |
| `passages` | list each sentence that cites a work, with the passage of that work recorded as supporting it and what G7 found of it; `--missing` lists those with none |
| `references` | whether each cited work is still the one to cite: alone, a row for each claim in scope (a sentence and a work it cites that `literature/currency.yaml` marks, or whose lookup record shows a later version or a published preprint) with how far its entry got; `--explain ID` its searches, how many readings are filed and what the rules give, and with `--readings` each reading's fields and quotes, which a reader still to read the entry does not ask for; `--mark "WORDS" @KEY` marks a claim; `--reading FILE` files a reading once, sealed, and writes the rules' decision once two are filed, and with `--replaces N` corrects its reader's reading N, which is then read no longer; `--refuse ID --why ... --as PERSON` records a person's refusal of a proposed change; `--search ID --terms "TERMS" --as WHO` runs the fixed searches for an entry (the cited work's forward links and citing reviews, systematic reviews, primary studies since the cutoff, ongoing trials, and with `--against` a query for evidence against the sentence), records each one sealed and fills the works store, `--question` writing the claim as a question, which is never sent; `--replay ID` runs the recorded searches again and lists the works new since; `--dry-run` prints the requests and sends nothing; `--comments` writes each unanswered proposal as a Word comment on its citing sentence, in `build/currency/suggestions.docx`, a copy for the authors and never for the journal, whose replies `import` files under `literature/currency/replies/`; `--assess ID --reply N --says WHAT --quote "..." --as READER` records whether a reply refuses, agrees or says something else, and a refusal by a person of `authors.yaml` answers the proposal. A claim of novelty or absence ("no study has examined") is listed too: `--novelty "WORDS"` marks it, with `--id` puts a reworded claim back into its entry, and with `--not-a-claim --why ... --as PERSON` records a person's word that it makes no claim about the literature; `--search ID --terms "TERMS" --not-searched "..."` runs its search for the earlier study (N1) and `--forward WORK` in place of `--terms` the works citing the nearest one found (N2); `--hand-search ID FILE --as PERSON` files a search a person ran by hand. It calls no model |

## Co-Authors & Review

| Command | What it does |
|---|---|
| `review` | show where the review panel stands, with the sections each reading's quotes fall in and the sentences two readers or more quote; `--ai-use` lists each model the records show at work and what it did, and the AI use `authors.yaml` declares, for the AI-use statement, and writes nothing; `--run` has it read by the models you list, `--seal` seals a reading written by hand, `--design` does the same for a design round, which reads the plan; `--suggestions` writes the edits a round's findings suggest into a Word document as tracked changes, for you to accept or refuse there and `import` |
| `checker` | send a co-author one file of things to confirm, record what they answered, and recap who checked what (`recap`, `recap --check`) |
| `import` | bring a co-author's Word edits back into the manuscript source, and file each of their Word comments as a finding to answer |
| `respond` | open a revision round, or write the point-by-point response |
| `approve` | record an author's approval of the manuscript as it stands, which `submit` holds to the manuscript sent; the author's own act |
| `sign` | record a named person's sign-off of a finding only they may close, a G15 warning for the statistician `authors.yaml` names, the journal's rules no gate checks for the corresponding author, a model provider the manuscript may be sent to for the data custodian; that person's own act |

## Build, Release & Communicate

| Command | What it does |
|---|---|
| `render` | substitute the bindings and stop there |
| `build` | produce the .docx, or for a LaTeX manuscript the PDF, compiled with latexmk in a copy; `--annotated` colours every number by what backs it; `--marked-up` also writes the revision, and its supplement, with every change since the documents the journal received shown as Word tracked changes, or highlighted (`--highlight`); `--latex` writes a Markdown manuscript as LaTeX, holds its digits to the Markdown's, and compiles it |
| `submit` | assemble the submission pack, with a checklist of the journal's rules no gate checks, and at a revision of a manuscript packed as Word the marked-up copy beside it; a LaTeX manuscript's source, or with `--latex` a Markdown one's, in one folder that compiles alone |
| `package` | write the package to deposit for reproducibility (Zenodo, OSF, a journal's repository): the scripts, the results and their digests, what they ran with, a README on running them again, CITATION.cff and the results the paper binds; an input goes in only when declared synthetic or shareable, never a restricted one; it uploads nothing; `--citation` adds `.zenodo.json`, `--ro-crate` describes the package as an RO-Crate stating only the links its files show to hold, the rest in RELATIONS.md, with the model cards, `--root-citation` writes the citation files at the project's root where none is, and `--companion` adds one self-contained page of the findings and the evidence for each, made from the records |
| `deposit` | stage a bundle for Zenodo, its sandbox, OSF, arXiv, medRxiv or a GitHub Pages site in `build/deposit/`, with an archive that is the same bytes from the same files: the analysis plan (`preregistration`, refused once results were written from it unless `--retrospective` says why), the package with its crate, its companion page and a VERIFICATION.md of how it was checked (`release`, refused while `check --stage submission` fails), or the paper (`preprint`: the LaTeX source as a `.tar.gz` for arXiv, the documents for medRxiv, each with a sheet of what the form asks); the data custodian's checks come first, a small count, a restricted input and, where they restrict sending, their sign-off of the bundle; it sends and pushes nothing unless asked: `--reserve-doi` makes a Zenodo draft with its DOI reserved and writes a release's into `paper.yaml` once you say yes, `--stage` sends the bundle to that draft or as a private OSF project, each file's md5 checked, and `--publish` publishes the draft only when the bundle is the one staged and you type its DOI at a terminal; the token is read from the environment, and each answer is kept in `deposit/receipts/` |
| `proof` | compare the publisher's proof (PDF, JATS XML, HTML or text) with the document in the submission pack, table cell by cell, and its title page with `authors.yaml`; list each changed number, sign, decimal mark, unit, citation, reference, name or affiliation, and each part left out, with its page and line, as corrections to send; nothing is sent |
| `communicate` | opt-in (`communication: {enabled: true}` in paper.yaml): `brief` writes `communication/brief.yaml`, the paper's own sentences, quoted, that every communication of it restates, with the primary finding for you to mark; `graphical-abstract` draws two concepts of a graphical abstract from it as SVG, at the journal's size, in Okabe and Ito's colours, with their alternative text; `check` holds the brief to the manuscript, and each text under `communication/` and the graphical abstract to the brief and the results: numbers bound, claims anchored and no stronger than the paper's, limitations kept, the publication status, the embargo, the journal's sharing policy, the platform's length; `build` writes each channel's text from the brief (posts and threads, an overview slide, a poster outline, a storyboard, a data announcement, translations), with slots for what only a person or an agent writes (a press release, a pitch, plain-language summaries, a script), and a `preview.html`; `status` says what is due given the publication's status and dates, and `--prepare` writes it; `approve --as <author> <channel>` records an author's approval of a text as it stands; `publish <channel>` writes what it would send to `communication/outbox/`, and with `--post`, which the author runs, posts it to Bluesky or Mastodon once it is checked, approved and past the embargo, with the credentials from the environment, and records what the service answered; LinkedIn is printed to paste and ResearchGate is by hand; `orcid` asks the authors' public ORCID records whether the paper's DOI is on them ([communicate.md](communicate.md)); nothing else sends anything |
